## 1. Fix these first

Five, chosen by severity × likelihood. Each states what breaks if it is not fixed.

### A1 — The wrapper guard is bypassable with `${IFS}` · CRITICAL · verified end-to-end

`hooks/wrapper_guard.py:51` requires a token to *end* in `codex_ro.py`
(`WRAPPER_TOKEN_RE = (^|[\\/])codex_ro\.(py|ps1)$`). Bash tokenises control operators
*before* parameter expansion, so:

```
python tools/codex_ro.py${IFS}&&<anything>
```

matches the recommended allowlist rule `Bash(python tools/codex_ro.py*)` at the start,
runs as two commands in bash, and the guard's `_invokes_wrapper()` never recognises the
first segment as a wrapper call — so `analyse()` returns `None` and the whole command is
allowed. Measured: guard exit **0** for the `${IFS}` form, exit **2** for a plain `&&`;
both halves of the real command executed. `grep -c IFS tests/test_wrapper_guard.py` → 0.

**If not fixed:** the single control that makes the allowlist entry defensible is
decorative. Any injected or mistaken builder agent gets one unreviewed arbitrary command
per wrapper call, with no permission prompt. This is precisely the trap the hook's own
module docstring says it exists to close.

**Fix:** stop deciding invocation from the token's tail. Detect the wrapper on a
normalised token (strip expansions first), and treat any token containing `$`, `${`,
backtick or `\` line-continuation in a command that mentions the wrapper as
"unresolvable → deny". Add the `${IFS}`, `$IFS`, `${x}` and `"$(…)"` forms to the test
suite as denial cases.

### A2 — `--allow-path` turns the allowlisted wrapper into a write/delete primitive · CRITICAL

`scripts/codex_ro.py:124-127` extends the allowed roots from `--allow-path` **and**
`CLAUDEX_ALLOWED_PATHS`. `--allow-path` is an ordinary flag, so it rides the same
allowlist prefix with no prompt. The wrapper then does `out_file.unlink()` (`:429`) and
`open(err_file,"wb")` (`:448`) inside those roots.

**If not fixed:** `python tools/codex_ro.py --allow-path / --out-file <any file> …`
deletes or truncates any file the user can write — approved as a "read-only review". The
module docstring's promise that an accepted call cannot obtain write access is false. A
TOCTOU window between `realpath()` and `unlink()`/`open()` sits on top of it.

**Fix:** the caller may not widen its own confinement. Drop `--allow-path` from the
unattended path (keep it only behind an interactive confirmation, or an operator-set
config outside the repo), refuse an `--out-file` that already exists rather than
unlinking it, and open with `O_NOFOLLOW`/`O_EXCL`.

### A3 — `-c mcp_servers.*` is accepted, and the MCP defaults are wrong in both directions · CRITICAL

Three problems in the same twelve lines of `build_argv` / arg parsing:

1. `FORBIDDEN_CONFIG_KEYS` (`:68-73`) covers only the four sandbox keys. User `-c`
   overrides are appended **after** the disable list (`:187-188`), so
   `-c mcp_servers.x.command=…` defines a command-backed MCP server. Codex launches MCP
   servers as separate processes **outside** the shell sandbox — that is a full escape
   from a call the allowlist approved.
2. `--disable-mcp ""` / `CLAUDEX_DISABLE_MCP=""` disables **nothing** (`:378-385`).
3. `DEFAULT_DISABLE_MCP = ("n8n", "MCP_DOCKER")` (`:64`) hard-breaks the wrapper on any
   machine where those servers are not configured: the synthesised
   `mcp_servers.MCP_DOCKER.enabled=false` has no `transport`, and Codex refuses to load
   its config at all — exit 1, empty answer file. **This happened on the first four
   sessions of this very audit.** It directly contradicts `:61` ("Naming a server that
   does not exist is harmless").

**If not fixed:** (1) is a sandbox escape; (3) means the plugin fails on a fresh install
with an error that points at the user's Codex config rather than at the wrapper.

**Fix:** reject every `-c` key under `mcp_servers` (the wrapper owns MCP, not the
caller); disable MCP globally with one switch instead of per-name guessing; and correct
the comment at `:61`.

### A4 — The roles resolver reports "gates OK" for arrangements its own doctrine forbids · HIGH

Two verified live:

- `roles: {plan: [claude], plan-review: cross}` resolves to
  `plan claude -> plan-review claude (cross-check)` with `producer_never_reviews : True`
  and **`gates OK`**. One author, zero, or the same actor twice all pass — the resolver
  certifies an independent review that does not exist.
- `producer_never_reviews: false` + `adversary_read_only: false` +
  `actors.codex.sandbox: danger-full-access` in a `.claudex.yaml` found in the CWD **or
  any ancestor** (`:170-175`) yields `gates OK`, exit 0, and
  `--spec audit → sandbox=danger-full-access`. ROLES.md:27 states the adversary "must be
  **read-only**"; ROLES.md:48 says the config lives "in the repo root", which the
  ancestor walk does not honour.

**Correction to the reviewer:** the `write_access` half of the gate is *not* disableable
— it still fired when tested on its own. Only the sandbox and producer halves are.

**If not fixed:** the component whose entire job is to answer "who is allowed to grade
this" can be talked into "the author does, with write access" by a file inside the repo
being reviewed — and will print `gates OK` while doing it. Today `codex_ro.py` still
pins `-s read-only` independently, so the sandbox does not actually open; the damage is
that the gate lies.

**Fix:** treat gate flags and the adversary sandbox as non-configurable — read them from
defaults only, never from repo-local config. Require exactly two *distinct* known actors
for `cross`. Resolve the repo root first and read only its `.claudex.yaml`.

### A5 — Egress defaults open; redirects and proxies are outside the policy · HIGH

`scripts/fallback_review.py` is the path that ships the plan, the review log and
whatever files the caller names to a remote model.

- **Default-open host policy.** With no `config/allowed_egress.yaml` and
  `CLAUDEX_EGRESS_ALLOW` unset, **any HTTPS host is accepted** — the docstring says so
  at `:313`, and the error text at `:352-353` even tells the reader to *unset the
  variable to drop the restriction*. The allowlist is fail-closed only once one exists.
- **Redirects are never re-checked.** `check_egress(url)` runs, then plain
  `urllib.request.urlopen` (`:370-372`, `:520-523`) follows 30x hops with its default
  handler. A permitted host can redirect the plan — and the `Authorization` header — to
  one that is not on the list.
- **Proxy env is honoured silently.** `HTTP(S)_PROXY` reroutes even a
  `http://127.0.0.1:1234/v1` profile; the loopback exemption checks the URL, not the
  transport.
- **`host.docker.internal` is in `LOOPBACK_HOSTS`** (`:200`) although it is an ordinary
  DNS name that anything can resolve — cleartext plan traffic to wherever it points.
- **Inputs are unconfined.** `--plan`, `--log` and `--system-file` (`:507`, `:715`) take
  any readable path with no root restriction and no redaction; `.env` or unredacted
  scanner output can be sent as prompt content.

**If not fixed:** the fallback path is a working exfiltration channel for repository
content, reachable through a `.env` that `load_dotenv()` (`:100`, `:666`) reads from the
target repo's own working directory.

**Fix:** require an allowlist for every non-loopback request and fail closed when it is
absent; install a redirect handler that re-runs `check_egress` per hop and strips
credentials on origin change; use a proxy-free opener for loopback and verify the
resolved address is actually loopback; drop `host.docker.internal`; confine `--plan` /
`--log` / `--system-file` to the repo and screen them for secrets.

## 6. What this is not

One adversarial pass over code by two models plus verification by a third. Not a
penetration test, not a compliance audit, and no exploit was weaponised beyond the
minimum needed to confirm A1. The `${IFS}` bypass was proven with `whoami` and `echo`.

## Remediation, round two — CodeRabbit

The fixes above were themselves reviewed, by a third model with no part in writing
them. Three passes of `coderabbit review --agent --uncommitted --include-untracked`,
**35 findings**, all verified against the code, all resolved. This section exists
because the result is the argument for the whole method.

| Pass | Findings | critical | major | minor |
|---|---|---|---|---|
| 1 | 13 | 1 | 7 | 5 |
| 2 | 6 | 2 | 4 | 0 |
| 3 | 16 | 0 | 7 | 9 |

**Count did not converge; severity did.** CodeRabbit's coverage is not deterministic —
each pass samples differently, and every fix creates new surface for the next one to
read. Chasing the count to zero would be optimising against a reviewer rather than
against the code. Three passes with the criticals gone was the stopping rule.

### What it caught that the audit did not

**A CRITICAL inside the fix for A1.** `_strip_expansions` handled `${...}` and `$NAME`
but not `$(...)` or backticks — and the substitution check in `analyse()` runs *after*
invocation recognition, which is precisely what those forms defeat. Measured: exit **0**
for `codex_ro.py$(echo)&&whoami`. A second cause surfaced only through the failing test:
shlex with `punctuation_chars=True` splits the parentheses off, leaving a bare trailing
`$` that matched no alternative. The `${IFS}` fix had closed one spelling of the hole.

**`--disable-mcp ""` warned instead of refusing.** The third door to the same room as
`--allow-path` and `-c mcp_servers`. A warning on stderr is not a control — nobody reads
stderr on a call that succeeded. Now exit 2.

**Three regressions introduced by the audit fixes themselves**, all in the class of
"changed the mechanism, missed a caller": the documented fallback command would have
failed on the now-mandatory `--append-log`; `_opener` keyed its proxy bypass on the
hostname rather than the verified resolution, so a bridge address got treated as local;
and loopback became *stricter* as soon as any allowlist was configured — a rule that
tightens the more policy you set is a trap, and it would have silently broken every
local LM Studio profile the moment someone added a remote reviewer.

**`Path.write_text(newline=)` needs Python 3.10** while the manifest promised 3.8. The
CI matrix added by the audit would have caught it on its own 3.8 runner, had it run.

### Where CodeRabbit was not followed

**The symlink TOCTOU, twice raised.** The proposed fix — opening each path component
through verified directory handles — needs `openat`, which does not exist on Windows,
this plugin's primary platform. A fix that cannot work where the tool runs is not one.
The exposure was removed instead: write targets may only sit in directories no other
local user can write to, screened per root and up every ancestor (`_is_private_dir`).
A target whose parents nobody else can write to has no race to lose. Residual risk: an
attacker already running as this user, who needs no race.

### Also in this round

The declared Python floor moved to **3.10** at the owner's request — chosen for CI as
the last version *without* `tomllib`, so it is the only one exercising the regex
fallback in `installed_mcp_servers()`. `pyproject.toml` gained a `[build-system]` block
(CI runs `pip install ".[dev]"`, which without it trips over the top-level `scripts/`,
`hooks/` and `tests/` directories). All five `actions/checkout` steps set
`persist-credentials: false`; the actionlint image is pinned to a digest. README
Option B (manual copy) was **withdrawn** rather than documented — it was never a working
install, and there is no per-user path Claude Code reads hooks from for loose skills.

### Confirmed in the wild, same day

A sister repo (`claude-cowork/support/IT-OFFICE`) independently hit **A3**: every Codex
call there aborted at config load because the wrapper disabled `MCP_DOCKER`, which that
machine does not have. It was worked around locally with `--disable-mcp n8n`. That
workaround is unnecessary from 2.2.0 — and `wrapper_drift.py` reports that repo's copy
as 2.1.0, i.e. still carrying all five holes. Copies do not update themselves, and the
drift reporter only speaks when called.
