# Audit note 2026-09-11 — the review scope was the wrong one for eight rounds

Status 2026-09-18 · fixed in `codex_ro.py` **2.5.0** (`--expect-workdir`, cwd in the header)
· plan review: 5 rounds, **never approved** (`MAX_ROUNDS`), then resolved by owner decision
and built · closing gate: **ran, ended red**, see §10.

This note replaces the `PLAN.md` and `PLAN-REVIEW-LOG.md` that sat in the repo root. It
records what happened, what was measured, what was rejected and why — so that nobody builds
the rejected design a second time.

## 1. The incident

On 2026-09-11 **eight Codex rounds** ran with the working directory in a production
documentation repo instead of the intended throwaway repo. Codex was handed that repo's
roughly 25 KB `AGENTS.md` — machine table, addresses, access paths — with a real customer
name in its taboo list. From round 2 on the prompt carried a read ban; every transcript was
checked: 0 shell calls, 0 file reads, no credentials left the machine. What went to the
remote model, went.

**Not a guard failure.** `hooks/wrapper_guard.py` correctly denied
`cd X && python …codex_ro.py` (`EXIT=2`). The gap was elsewhere:

| Place (as of 2.4.0) | State |
|---|---|
| `Popen([...])` without `cwd=` | Codex silently inherits the caller's cwd |
| Header line | names mode, model, effort, timeout, version — **not** the working directory |
| Non-repo warning | the negative case only; in the normal case nobody says anything |

The working directory does not merely decide what gets reviewed. It decides **which
`AGENTS.md` Codex pulls into the prompt unasked**. It is an egress parameter — and it was
invisible and unverifiable.

## 2. The rejected design: `--workdir DIR` — ⛔ do not propose it again

The first draft wanted a **selector**: the caller names the target, the wrapper sets
`Popen(cwd=…)`. Codex took that apart as **CRITICAL** in round 1, rightly:

> Setting child `cwd` chooses which `AGENTS.md` and project context Codex auto-loads — the
> exact data-exposure mechanism described by the incident. “The sandbox can already read
> broadly” is irrelevant: this flag gives an unreviewed caller a new way to make Codex
> discover and send a chosen directory’s instructions/context, including UNC/network paths.

The draft's reasoning confused **read access** with **automatic ingest**. And because the
allowlist is a **prefix** rule (`Bash(python tools/codex_ro.py*)`), the flag would arrive
unattended. Whoever later wants a mechanism by which a caller *chooses* the scope is arguing
against this finding.

| | Selector (rejected) | Assertion (built) |
|---|---|---|
| Flag | `--workdir DIR` | `--expect-workdir DIR` |
| Effect | sets the child's cwd | compares with the actual cwd |
| Possible outcome | a different scope gets reviewed | **refusal**, or carry on as before |
| For an unattended caller | a new power | nothing but a refusal |

Negative invariants, kept as regression tests: the wrapper never calls `os.chdir()`, `Popen`
gets no `cwd=`, the expectation value never reaches `allowed_roots()`.

## 3. Measurements

| Measurement | Result |
|---|---|
| Bash tool, a lone `cd <elsewhere>` | harness: *"Shell cwd was reset to …"* |
| PowerShell tool, `Set-Location` + `Get-Location` | holds **within** the call, then the same reset |
| One call that changes directory **and** starts the wrapper | denied by the guard (`EXIT=2`) |
| `os.path.realpath("") == os.getcwd()` | **True** |
| `os.path.realpath("missing/..") == os.getcwd()` | **True** |
| `ntpath.abspath()` of `\repo`, `D:\repo\scripts\..`, `D:\repo. `, `D:\repo\.` | all four → `D:\repo`; `ntpath.isabs('\repo')` is **True** on Python 3.12 |
| `os.symlink` on the development machine | `WinError 1314` (privilege missing) — alias tests need a junction or a mock |
| `realpath(cwd) == cwd` for this repo (2026-09-18) | True — the normal case is alias-free |

**From the first three rows:** there is exactly **one** supported way — a session that
**starts** in the target directory. Reviewing another repo from a foreign session is not
supported. The human chooses the scope when starting the session, not an unattended flag;
`--expect-workdir` is the net underneath.

**From rows four and five:** a fallback to `realpath()` for "non-existent" expectation
values (the round-2 draft) would have normalised an empty `$TARGET` to the cwd — the run
would have **confirmed itself**. An assertion that waves through on failure is worse than
none. There is no fallback, and the expectation value is never resolved at all.

**From row six:** see E-1 below — the first build fell into it anyway.

### Does Codex canonicalise the cwd before it looks for `AGENTS.md`? — No (source, 2026-09-18)

Rounds 4 and 5 demanded this; it was settled on 2026-09-18 — **against the source of the
installed version**, tag `rust-v0.149.1` (commit `980a6d1`), not against `main` and not from
memory. A live run inside a junction was **not** done (it would have had to start the wrapper
from another cwd, which §3 just ruled out).

| Question | Finding | Place |
|---|---|---|
| Where does the cwd come from without `-C`? | `std::env::current_dir()`, then absolutised **lexically** only (`.`/`..` removed) — no filesystem access, no link resolution | `codex-rs/exec/src/lib.rs:312-318`, `utils/absolute-path/src/lib.rs:82-84`, `absolutize.rs:14-45` |
| Is it canonicalised? | Only on the `-C` branch (`dunce::canonicalize`), and even there a link **below** the root is deliberately left unresolved | `utils/absolute-path/src/lib.rs:207-224` |
| Where does the `AGENTS.md` walk start and stop? | At the cwd as given, upwards to the nearest `project_root_markers` hit (default `.git`); without a hit, the cwd alone. No canonicalisation in that file | `codex-rs/core/src/agents_md.rs:199-277` |

⚠️ Not traced: the hop from `Config.cwd` through the turn environment to `agents_md.rs`. An
extra canonicalisation there is conceivable; none was found.

**Consequence:** the wrapper passes no `-C`, so Codex walks the **logical** ancestor chain of
the inherited cwd. On Windows a process's cwd is a logical string — a session started through
a junction pulls the `AGENTS.md` from the junction's branch, not the target's. Round 4 HIGH 1
was **not a theoretical objection**. Decision E-1 below holds either way; it does not depend
on this reading, but is confirmed by it.

## 4. What the five plan-review rounds found

| Round | Verdict | Load-bearing finding |
|---|---|---|
| 1 | REVISE (1 CRITICAL) | `--workdir` is an egress selector → design overturned, selector → assertion |
| 2 | REVISE (3 HIGH) | no usable way to reach the target shown (→ measurements §3); `$TARGET` as a rubber stamp; Windows path equality |
| 3 | REVISE (2 HIGH) | the `realpath` fallback added in round 2 makes the control **fail-open** — introduced by the author while repairing another finding |
| 4 | REVISE (2 HIGH) | `samefile()` proves leaf identity, not ancestry; the lexical refusal could be walked around with `./`, `//srv` |
| 5 | REVISE (3 HIGH), cap | the "ancestry" condition from round 4 was inert (`realpath` resolves aliases by definition); "capture the cwd once" contradicted "`allowed_roots()` unchanged"; the skill stanza was a placeholder with no binding |

Nothing was rejected in five rounds. The run ended at the cap, not at an agreement and not at
a stalemate. **Two of the four revision cycles introduced the very defect the next round
found** — see §11 for what that suggests about the loop itself.

## 5. The decisions of 2026-09-18 (resolving the three open points)

**E-1 — purely lexical comparison of the logical path.** The expectation value must be
absolute and is checked **without any filesystem access**: empty, control characters,
network/device prefix (a leading `//` after `\`→`/`), not absolute → refusal. Then
`normcase(DIR) == normcase(cwd)` — the value **as typed**; the only tolerance is case and
slash direction (Windows) and one trailing separator. ⚠️ The first build compared
`normcase(abspath(DIR))`; `abspath()` normalises, and `<cwd>\sub\..`, `<cwd>\.`, a trailing
dot or space and the drive-rooted `\repo` were therefore **accepted**. Found by the closing
gate, not by the tests (§10). In addition the **cwd itself must be alias-free**
(`normcase(realpath(cwd)) == normcase(cwd)`), which makes the logical and the physical
ancestor chain the same — whether or not Codex canonicalises the cwd before looking for
`AGENTS.md`. Only after that, as a belt, `samefile(cwd, DIR)`; because the strings are
already equal by then, it never reaches a foreign path. Every exception is a refusal; the
message shows the two paths only, escaped.

Price paid on purpose (fail-closed): every **other spelling of the same place** is refused
— symlink/junction alias, 8.3 short name, `subst`/mapped-drive alias, a case variant on
macOS. The way out is to name the cwd path the message shows. Relative values are not
allowed; the skill contract only knows absolute ones anyway.

**E-2 — `allowed_roots(…, cwd=None)`.** `main()` captures the cwd once and passes it on; the
root policy does not change by a single root. The promise reads precisely: *the expectation
value never reaches `allowed_roots()`.*

**E-3 — the binding is an instruction, and the test admits nothing but the placeholder.** A
skill argument reaches the shell only through whoever executes the skill; no parser is
pretended. All invoking skills and `docs/betrieb.md` carry the same, byte-identical section
(`<!-- claudex-target:begin/end -->`); the only right-hand side of `TARGET=` permitted in a
shell fence is `'<target= argument>'` — copied unchanged it fails closed. No skill can ever
ship `TARGET="$PWD"`.

## 7. Second finding: the taboo scope named a customer

The list meant to prevent exposure was itself the exposed item — it lives in `AGENTS.md`, and
that goes into every prompt. Rule since 2.5.0 in `skills/setup/SKILL.md` and `AGENTS.md`:
taboo entries are **path-neutral / categorical**, never with a real customer, person or host
name. The matching contract test is labelled weak: all it can check is that the rule is in
the skill, not that it works. A pre-flight scan of a target repo's `AGENTS.md` before it is
first auto-loaded would close this properly — see §11, upstream PR #22.

## 9. Rollout

All 13 repos under `develop\_dev\projects\` stood at 2.4.0 on 2026-09-16. 2.5.0 goes into
each repo's **next commit that is due anyway**, not into 13 commits of its own (review
quota):

```bash
python scripts/wrapper_drift.py --repo "<absolute path>" --update
```

⚠️ `--scan` only sees one or two levels below ROOT — silence there is not proof. Check each
target individually with `--repo`. Do not use `--update-optional` blindly (several repos carry
local changes to `codex_usage.py` / `fallback_review.py`).

⛔ **Order: the wrapper copies first, then the skills.** The skills are part of the plugin and
apply to **every** repo the moment it is updated; the wrapper is a per-repo copy. A repo on
2.4.0 does not know `--expect-workdir` and aborts every skill call in argparse
(`unrecognized arguments`, exit 2) — loud, not silent, but reviews stand still until the copy
is updated. 2.5.0 is backward compatible (the flag is optional), so it is safe to roll out
ahead. The canonical section in the skills names this case and forbids "fixing" it by
dropping the flag.
